Admin Model

The admin pages edit the CMS database directly. Public requests are still served by the CMS router: it resolves redirects, finds published content by path, renders the body, and wraps the result in the active theme.

The admin UI is hard-coded and independent of public themes. Changing the active theme affects public pages, not the admin pages.

Content

/admin/content/ lists pages and posts from the content table. Use All, Pages, and Posts to filter by content.type.

FieldPurpose
typepage for ordinary pages, post for article/blog-style entries.
pathPages store their public path. Posts store only the article path; the configured blog base is added automatically. Paths should start with /.
statusOnly published content is served by public URL lookup. draft content remains editable but hidden.
render_modehtml sends stored HTML as content. lsp parses stored body content with ba.parselsp() before rendering.
body_htmlThe main page or post body. LSP tags are allowed only when render mode is lsp.
head_htmlExtra markup inserted by the public theme into the document head.

Editing Rules

  • Changing a path changes the public URL immediately. Add a redirect for the old path when preserving inbound links matters.
  • LSP content executes as trusted server-side code with the active public app table. Use it only for administrator-controlled content.
  • Draft content can still appear in admin lists but is not returned by the public route lookup. Use Preview in the content list or editor to render a draft at its real path with a cms-preview query parameter.
  • Delete permanently removes content; there is no trash or restore feature. The confirmation page lists child paths, linked menu items, and related redirects. Child content is preserved, and the active editable 404 page cannot be deleted.

Categories

/admin/categories/ manages blog categories. A category slug is used in its archive URL and can be generated from the name by leaving the slug blank.

  • Assign categories in the Content editor when the content type is post.
  • Category archives use <blog base>category/<slug>/.
  • Deleting a category removes its assignments but does not delete posts.
  • Trusted LSP pages can list published posts with app.cms:postsByCategory("slug", { limit = 20 }).

Menus

/admin/menus/ edits rows in menu_items for the primary menu. The public theme decides how the tree is displayed.

  • label is the visible menu text.
  • url can point to CMS content or any internal/external URL.
  • parent_id nests one item under another. Leave it blank when adding a row to auto-select the closest visible parent by URL prefix.
  • position controls ordering within the same parent.
  • Hide marks a row hidden. Hidden rows stay editable in admin but are excluded from public navigation.
  • Delete permanently removes only the menu item, not its target content. Any child menu items are preserved and become top-level items.

Redirects

/admin/redirects/ manages redirects. Redirects are checked before normal content lookup.

  • from_path is the incoming URL path.
  • to_path is the target URL.
  • status_code should be 301 for a permanent redirect or 302 for a temporary redirect.

Themes

/admin/themes/ persists the selected theme in options.active_theme. Themes live outside the CMS app under the shared themes directory.

  • The public theme supplies LSP templates such as layout, page, post, and archive.
  • Theme assets are exposed under /theme/ by the CMS theme loader.
  • Changing the active theme reloads its resource reader and compiled templates immediately. A normal theme switch does not require a Mako restart.

Settings

/admin/settings/ controls public behavior persisted in the options table.

  • The blog base URL selects the published-post archive path.
  • HTMX navigation enables fragment responses; the active theme must implement the matching full-page and fragment contract.
  • SMQ real-time messaging is available only with HTMX. It keeps one broker connection in the public shell while HTMX pages mount temporary event, direct-message, and RPC scopes.
  • The editable 404 option installs a low-priority VFS callback and renders the selected published CMS page with HTTP status 404.

Users

/admin/users/ manages TPM-protected admin users. With no users, admin authentication is disabled. Adding the first user enables form authentication for the admin directory; removing every user disables it again.

MCP

/admin/mcp/ configures the bearer token for the mount-aware MCP Streamable HTTP endpoint at /mcp/. Use that exact directory URL in MCP Inspector, not /mcp.lsp. The endpoint is disabled until a token is saved.

  • The token is encrypted in SQLite with a TPM-derived key and is never displayed after saving.
  • MCP content creation and copying default to drafts. Ordinary updates preserve status; publishing and unpublishing use an explicit status operation.
  • The MCP server publishes capability details, guides, examples, workflow prompts, and safe operational diagnostics in addition to administration tools.
  • Selected pages and posts can be transferred between CMS servers using one-time ZIP snapshots. Transfers include content metadata and taxonomy assignments.

Operational Notes

  • Do not expose admin pages on an untrusted network until at least one admin user exists.
  • Database writes use the dedicated CMS SQLite writer thread. Public reads use separate short-lived read connections.
  • If the database is absent, startup creates the schema and an editable /404/ page that links back to admin.
